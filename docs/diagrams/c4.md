# C4 diagram

**Type id:** `c4` · **Sub types:** `context` (default), `container`, `component` · **Has arrows:** yes (relationships) · **Custom colours:** no (four fixed colours per element) · **Line weight:** medium by default
**Rust crate:** `crates/diagrams/hiero-c4`; its shapes are in `hiero-core/src/c4.rs`
**Reference:** <https://c4model.com> (no prototype: new in the Rust app)

One type for the C4 model's three levels: a **system context** diagram (a software system,
its people, and the systems around it), a **container** diagram (the applications and data
stores in a system), and a **component** diagram (the parts of a container). Which level a
diagram shows is its **sub type**, chosen in Edit Details (and when adding it). The sub type
only names the diagram, as in its header's "C4 - Container diagram" and the list's
"C4 - Container": every level offers the same elements and relationships.

## Sub type

| Sub type | Label | Stored |
|---|---|---|
| `context` | Context | Left out: it's the default |
| `container` | Container | `"subtype": "container"` on the diagram |
| `component` | Component | `"subtype": "component"` |

It's kept in the `diagrams.subtype` column (migration 7), in versions, and in the content
hash, and changing it in Edit Details is one undo step. Agents set it with `create_diagram`'s
and `update_diagram_details`' `subtype`.

**Add diagram** on an element starts the new diagram, which is a C4 diagram unless its type is
changed in the form, from the element:

| Element | Sub type | Starts with |
|---|---|---|
| System | Container | A boundary named after the system, at (40, 40) |
| Container | Component | A container boundary named after the container, at (40, 40) |
| Anything else | One level below its diagram's: context → container → component | Nothing |

The sub type can still be changed in the form; the boundary is added whichever is chosen.

Migration 7 replaced the three earlier types, `c4-context`, `c4-container`, and
`c4-component`: their diagrams were deleted, with their versions; a sub diagram of one stays,
on its own.

## Elements

The palette offers **Person**, **System**, **Container**, and **Component**; then, under a
**Boundaries** heading, **System** and **Container**, each adding a boundary of that type named
after it; then, under a **Containers** heading, each kind of container (**Website**, **Static
Content**, **Backend**, **Service**, **Queue**, **Topic**, **Store**, **Database**), each adding
a `container` of that type named after it. **Container** at the top adds the generic box. A
container's or boundary's type can be changed in its properties afterwards. Agents see the five
kinds.

All sizes are in canvas pixels and multiples of the 20 px grid. Every element is resizable,
and has a name, a description, and a **Colour**. Everything but a boundary shows its name in
bold (16), its type in square brackets (11), and as much of its description as fits (13):
inside its shape, or for a person in their box, under their circle. A boundary shows them in its bottom-left
corner.

| Kind | Label | Default size | Can contain | Drawn as |
|---|---|---|---|---|
| `person` | Person | 200×160 | – | A box with round corners holding their text, and a circle (radius 30) centred on its top edge, like a profile picture. The circle is white, and holds the actor figure's head and shoulders in the person's colour, set low so the circle crops the shoulders, with no line along their bottom. The box is in the person's colour too. Type `[Person]`, or its own **Type**. |
| `system` | System | 240×140 | – | A box with round corners. Type `[Software System]`, or its own **Type**. |
| `container` | Container | by its type (below) | – | Its **Container type**'s shape. Type `[Container]`, or `[Container: technology]`. |
| `component` | Component | 240×140 | – | A box with round corners and two small tabs sticking out of its upper-left edge. Type `[Component]` or `[Component: technology]`. |
| `boundary` | Boundary | 600×400 | person, system, container, component, boundary | A line with round corners and no fill, in its colour, round what it holds. Its name, type (`[Software System]`, or `[Container]` for a container boundary), and description (one line) sit in its bottom-left corner. Header 20, footer 60, padding 20. Takes no arrows. |

Boundaries are drawn behind everything else on their own, and hold any element, other
boundaries too, such as a container boundary inside its system's. An element can't be put
inside itself or anything it holds: the properties panel doesn't offer it, and an agent's edit
that tries is refused.

### Container types

| `containerType` | Label | Default size | Shape |
|---|---|---|---|
| left out | Default | 240×160 | A box with round corners. |
| `web-application` | Website | 240×160 | A browser window: a bar across the top in the border colour, with three dots and an address bar. |
| `static-content` | Static Content | 240×160 | A folder, with a tab on its top-left. |
| `backend` | Backend | 240×160 | A box with a prompt (`>_`) in its top-left corner. |
| `service` | Service | 200×160 | A hexagon pointed on its left and right, for a microservice (<https://c4model.com/abstractions/microservices>). Its points stand out as a regular hexagon's would, but no more than a quarter of its width; its text is inset by half a point. |
| `queue` | Queue | 240×120 | A cylinder on its side, its open end on the left: a message queue, which one consumer takes each message from. |
| `topic` | Topic | 240×120 | The same cylinder: a topic, which every subscriber gets each message from. |
| `store` | Store | 240×160 | A bucket: an elliptical top, narrowing to the bottom. |
| `database` | Database | 240×160 | A cylinder. |

A container that hasn't been resized takes its type's size; arrows end on a service's hexagon
and a queue's or topic's cylinder, not their boxes.

Following <https://c4model.com/abstractions/queues-and-topics>, model each queue and topic as
its own container: publishers point to it ("Publishes messages to"), and subscribers point to
it too ("Subscribes to messages from"). A point-to-point coupling can instead leave the queue
out and put `via Queue X` in the relationship's technology.

## Element properties

| Field | Applies to | Rule |
|---|---|---|
| Name | all | Required, at most 100 characters |
| Container type | container | A select of the types above, *Default* the plain box. Stored as `containerType`, left out for the default. |
| Boundary type | boundary | Radio: *System* or *Container*. Stored as `boundaryType`: `"container"`, left out for a system. |
| Type | person, system | At most 40 characters, shown in square brackets in place of `[Person]` or `[Software System]`, such as `[Customer]` or `[External System]`. Blank shows the usual type. Stored as `typeName`. |
| Technology | container, component | At most 60 characters, shown in the type line. |
| Description | all | At most 500 characters, keeping line breaks. |
| Colour | all | Radio: *Blue*, *Green*, *Orange*, or *Red*. Stored as `color`: `"green"`, `"orange"`, or `"red"`, left out for blue. By C4's custom, blue is the software system in scope and what's in it, orange another of the organisation's own systems, and red a system outside it. |
| Parent | all | The boundary it sits in, or none |

## Colours

The colours are fixed, taken from the other diagram types; text is the usual dark text.

| Colour | Fill | Border |
|---|---|---|
| Blue (a physical diagram's blue zone) | `#dae8fc` | `#2d5f9e` |
| Green (a physical diagram's green zone) | `#d5e8d4` | `#356b24` |
| Orange | `#ffe6cc` | `#b46504` |
| Red (a physical diagram's red zone) | `#f8cecc` | `#9c3530` |

People are filled in their colour with a `#1e1e1e` outline. Boundaries have no fill, and their
line is drawn in their colour.

## Relationships (arrows)

The app calls a C4 diagram's arrows *relationships* everywhere it names them: the properties
panel (*Relationships*, *Add relationship to*, *Remove relationship*), announcements
("Relationship from Customer to Banking added."), and the errors of file checks and MCP edits.

- **Drawing:** drag from the round handle on the selected element to any element but a
  boundary, or use *Add relationship to*. Routing is the shared side-to-side routing:
  straight where the two elements' facing sides overlap. A relationship at a person's top ends
  on their circle, or on the top of their box beside it.
- **Look:** a black (`#1e1e1e`) dashed line, 2 px, with a filled head. Its description sits
  centred on the middle of the line, split evenly at spaces into lines of at most 20
  characters (so one a little over 20 is split in the middle), over a white halo, with its
  technology under it in square brackets at 11 px.

| Field | Rule |
|---|---|
| Description (`description`) | At most 150 characters, such as "Makes API requests to" |
| Technology (`technology`) | At most 60 characters, such as `JSON/HTTPS` |

Removing an element removes its relationships.

## Export

- **SVG:** the shared scene.
- **draw.io:** a person is an empty cell that takes the arrows, with their box (holding the
  text) and their circle (a stencil) as its children; systems, components, and
  plain containers are rounded boxes; boundaries are draw.io containers, nested as on the
  canvas, with their text at the bottom left. A website is a rounded box with its bar, dots,
  and address bar as child shapes; static content is draw.io's `folder`; a backend a rounded
  box with a `>_` text child; a store a bucket stencil; a database draw.io's `cylinder3`; a
  queue or topic `cylinder3` turned to face north; a service draw.io's `hexagon` with a fixed
  point of the same size; a component's tabs are child shapes. Relationships are attached
  dashed connectors with their description and technology as the edge label on the middle.

## Stored data

```jsonc
// diagram
{ "type": "c4", "subtype": "container" }          // subtype left out for "context"
// element props
{ "color": "red" }                                // any element: "green" | "orange" | "red"; omit for blue
{ "typeName": "Customer" }                        // person, system; omit for the usual type
{ "containerType": "database", "technology": "MySQL" }  // container
{ "technology": "Spring Bean" }                   // component
{ "boundaryType": "container" }                   // boundary; omit for a system
// connection props
{ "description": "Reads from and writes to", "technology": "SQL" }
```

Rust shape: `Element<C4Kind, C4Props>` and `Connection<C4Arrow>`.
